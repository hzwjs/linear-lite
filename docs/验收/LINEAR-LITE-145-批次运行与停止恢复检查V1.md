# LINEAR-LITE-145 批次运行与停止恢复检查 V1

## 运行与恢复契约

宿主以批次标识和运行代次保存运行、尝试和进程记录。两个批次可绑定同一物理目录。服务端按任务领取权限制同一任务的活动尝试，停止确认前保留原尝试的归属。预算、已用尝试数、截止时间和绑定版本以服务端持久状态为准。

接受批次前，宿主调用 `batches/prepare-accept` 并将停止专用凭据存入钥匙串，再带该凭据调用 `batches/accept`。凭据绑定原设备授权、绑定版本、批次、宿主实例和预期代次。接受请求结果未知时，`recovery/finish-accept` 在项目事务内结束仍待接受的批次，或收口原宿主和代次下尚无尝试的接受结果。运行凭据与准备凭据分开保存。

领取响应未知时，`recovery/recover-claim` 核对原领取标识、输入版本和执行归属。缺少领取回执时在同一项目事务封存原操作标识，阻止迟到请求创建尝试。拒绝回执可确认没有产生尝试，成功回执进入该尝试的停止流程。

本机停止先封存尝试的编辑入口，再等待在途编辑和登记进程组退出。重启恢复使用原目录、原代次及本机记录，校验 App Server 和受管编辑进程。进程状态或归属不明时保留对应记录。同批次的其他尝试可以分别确认停止。宿主按服务端回执释放未产生尝试的预算预留，已产生的尝试保留预算计数。项目绑定变更向该绑定发出停止意图，用户可在停止确认后重试保存或删除。
