# LINEAR-LITE-122 与 123 宿主与项目绑定交付记录 V1

日期：2026-11-10。对应任务：LINEAR-LITE-122、LINEAR-LITE-123。交付位于当前工作区，未提交、部署或启用定时任务。

## 交付结果

122 提供 macOS Codex App Server 宿主、状态驱动执行池、写入门、内容检查点、停止恢复与本机身份服务。123 在项目设置中提供用户、项目、设备绑定的查看、保存和删除。Pi 的 job/session 执行链保持原用途。

执行池使用 App Server 线程承载 Agent，不使用 Codex 原生 subagent API。Agent 从共享环境选择任务，服务端裁决领取、依赖、资源范围和输入版本；宿主不按卡分派工作，不依赖 Agent 点对点进度消息。

## 用户、项目、设备与目录

- 绑定事实来自 `project_device_binding`，当前认证用户、项目、设备组成绑定范围；同一组合沿用一条记录。
- 设备标识来自宿主状态目录中的持久身份；进程启动产生本次 `hostInstanceId`。浏览器不生成设备标识，Pi 目录不参与该数据路径。
- 项目根目录是唯一可维护目录，`docs` 从根目录派生。宿主验证设备、绝对路径、物理路径和目录项拼写，不存储第二套项目映射。
- 物理根目录锁以文件系统设备号与 inode 标识目录，覆盖项目别名及跨项目占用；租约看似过期不能成为夺锁依据。
- 本机元数据服务监听 `127.0.0.1:9781`，提供身份与目录校验；校验 Host、配置的站点 Origin、请求方法和 JSON 请求，不提供执行或凭据接口。

## 痕迹协作与停止恢复

1. 宿主读取绑定、取得物理目录锁、签发固定绑定的批次授权；凭据进入 macOS Keychain，Agent 不持有凭据。
2. 槽位中的 Agent 观察环境，选择 READY 任务并竞争领取；领取失败或观察到版本变化后，执行池依据环境补充槽位。
3. 普通命令在只读封套中执行；文件变更通过宿主写入门完成。写入门限定持有范围，拒绝符号链接、硬链接、大小写别名、特殊文件和 Git/宿主私有状态路径。停止后封存写入能力并等待在途写入结束。
4. 宿主每 10 秒续租。服务端返回带时区的到期时间和本次响应时钟，宿主转为单调时钟截止点；重放旧回执不能恢复过期租约。数据库北京时间 DATETIME 与外部 UTC 时间点按单一路径转换，精度按数据库秒保存。
5. Agent 留下发现、阻塞事实和成果引用；交付时宿主保存文件内容、目录及删除记录。下游声明前置成果可用前，核验快照与共享目录现状。Agent 无 Git 暂存或提交入口；本轮宿主采用内容快照，不执行 Git add/commit。
6. 取消、输入失效、续租或协作请求失联、检查点遭拒时封存写入并请求停止。运行中的回合须取得对应线程/回合结束事件，完成写入排空后，宿主向服务端提交停止确认；不具备证据时保留冻结资源和恢复关联。
7. 崩溃恢复先核实原宿主进程退出，再读取服务端尝试、持有范围与检查点。若服务端领取成功而宿主尚未保存领取凭据，使用原签名批次和领取操作回执验证归属，执行停止恢复，不向调用方补发领取凭据。归属、签名或停止确认失败时保留冻结。

恢复证明的范围是“原宿主退出，受控项目写入能力停止”；不声称枚举或终止全部 Codex 后台进程。恢复关联文件保存定位字段，不复制服务端尝试状态、资源范围和检查点事实。

执行池区分 COMPLETE、依赖/资源/活动执行等待、空查询、预算耗尽、用户停止、业务决策与恢复待处理。空查询不视为完成；Agent 提出业务决策后，停止活动槽位与补槽，将原因写入停止请求并返回 DECISION_REQUIRED。

`plan` 输出北京时间 01:00（`0 1 * * *`、`Asia/Shanghai`）的禁用计划，`enabled=false`，不注册系统任务。

## 项目设置与接口

项目设置使用现有组件与设计令牌，设备选择器展示本机和同用户同项目的其他设备。本机绑定可维护，其他设备绑定供查看。宿主不可用、目录缺失、设备失配或权限失败时阻止写入；执行占用或冻结导致的保存/删除冲突展示后端原因并保留绑定记录。项目与登录身份切换后，旧请求响应不能覆盖新页面。

本轮补充三项共享领域操作，REST 与 MCP 使用同一服务：

| REST 路径（前缀 `/api/collaboration`） | MCP 工具 | 用途 |
| --- | --- | --- |
| `/bindings/list` | `list_project_device_bindings` | 当前用户在项目中的设备绑定，返回 `{bindings}` |
| `/attempts/recovery` | `get_collaboration_recovery` | 使用领取凭据读取停止恢复事实，不授予续租或写入权 |
| `/attempts/recover-claim` | `recover_unacknowledged_claim` | 领取应答丢失后的停止恢复，验证原批次和操作回执 |

协作接口共 17 项，MCP 工具目录共 35 项。REST 响应提供 `X-Linear-Lite-Server-Time` 和 `Cache-Control: no-store`；响应时钟在领域操作后生成，不进入幂等回执。新增查询沿用认证用户与项目权限约束。本轮未新增数据库结构或执行数据库操作。

## 使用边界与后续工作

宿主执行接入限定 macOS；其他系统拒绝启动。受控修改支持 UTF-8 文本文件、创建目录和删除普通文件。项目设置的绑定展示与 `docs` 派生覆盖不同系统的路径形式，不等于执行宿主支持其他系统。

本轮单元/接口测试使用模拟协议与服务响应；原生探针没有模型业务执行。真实模型业务批次、十几个小时的连续运行、浏览器 E2E、部署及定时启用没有执行，不能将开发验证作为这些场景的运行证明；实际运行与定时启用按卡片约定等待后续指令。

操作方式见 [122 宿主使用与运行边界](../开发指引/LINEAR-LITE-122-Codex宿主使用与运行边界V1.md) 和 [123 项目设备绑定设置契约](../开发指引/LINEAR-LITE-123项目设备绑定设置契约V1.md)。
