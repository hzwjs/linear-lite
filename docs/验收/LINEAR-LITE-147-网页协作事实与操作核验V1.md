# LINEAR-LITE-147 网页协作事实与操作核验 V1

## 网页操作

1. 在任务详情写明需求和完成条件。在项目任务列表选中本次目标，点击「启动协作批次」。
2. 核对所选任务、执行设备和项目目录，设置运行时长并确认启动。项目设置的「项目目录绑定」和「本地执行」用于绑定目录及连接设备。
3. 在「协作执行」查看批次状态、服务端并发上限、尝试预算和截止时间。选择「停止批次」提交停止意图，详情按宿主回执显示停止确认或待恢复。
4. 启动结果待确认时，回到原账号和项目的「协作执行」，选择「重试上次启动」。浏览器保留该次请求和操作标识，刷新或关闭页面后的重试沿用原请求。放弃重试只清除浏览器记录，批次停止由「停止批次」处理。
5. 展开任务详情的「协作事实」，或查看批次内的任务详情。页面展示发现、缺交付、成果复核、采用资料、实际改动路径和交付证据。缺少本机读取事实的资料显示待确认。
6. Agent 提出超出当前目标的工作时，查看「新增业务目标」及影响，确认授权后可从同处打开新批次。服务端沿用原执行设备、目录绑定版本和用户选择的时长，为新批次分配预算。已确认的返工请求定位到原来源任务和交付版本，独立目标按获批内容生成任务，系统维护关系和新批任务集合。

## 接口核验

| 场景 | 结果 |
| --- | --- |
| 固定任务集合启动 | 网页请求发送项目、设备绑定及版本、所选任务、运行时长和幂等标识，服务端决定并发和尝试预算 |
| 观察任务状态 | 状态读取按任务标识取得服务端当前输入版本和执行事实，编辑器使用请求前的状态标记拦截切任务和保存竞态 |
| 执行与复核 | 两处详情共用协作事实组件，停止与恢复根据服务端时间、租约和停止确认展示，复核观察使用当前成果状态 |
| 目标授权 | 原批所有者确认，服务端校验原尝试和当前任务版本，返工校验同绑定来源交付，幂等回执对应同一新批次 |
| 目录与设备 | 现有目录绑定、设备授权、连接和停止流程通过组件回归 |

前端使用 Vitest 对 `src` 下受影响的 16 个文件运行组件、状态和 API 测试，109 项通过。使用 `npm run build` 完成 Vue 类型检查与 Vite 生产构建，构建产物写入临时目录。

服务端使用 JDK 21 运行批次控制、任务状态、领取、上下文、目标授权、前置复核和关系服务的 10 组 Maven 测试，115 项通过。

本轮检查使用本地测试和模拟回执。服务器部署、真实浏览器联调、真实模型及定时任务未执行。LINEAR-LITE-144 的受管可写命令保留待决。
