# LINEAR-LITE-150 痕迹协作 V2 单协议切换与回滚

本次发布组由 Java 服务及其内置网页、宿主 V3.0.1、协议 2 和当前数据库结构组成。切换以获准的维护窗口为单位。发布准备与实际切换分别记录。[发布准备清单](../验收/LINEAR-LITE-150-发布准备清单与核验V1.md)

## 切换顺序

| 阶段 | 操作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 确认现状 | 记录目标环境、当前 Java 包和网页、宿主版本、服务启动方式、实际入口、DBX 连接及结构。将原服务器外置配置、附件与文档存储位置、宿主状态目录及安装包纳入备份清单 | 原版本及运行入口可追溯，数据库结构满足 [DBX 指引](../开发指引/LINEAR-LITE-150-DBX预检备份与结构执行V1.md) 的基线 |
| 停止接受旧执行 | 先停旧协议的批次创建、业务目标授权、接受和领取入口，覆盖网页、实际暴露的旧 REST/MCP 及直连端口。维护入口保留旧批次停止、执行归属核验和旧协议恢复，沿用原授权与签名材料 | 新的旧协议执行无法进入，仍能在原版本发起停止和恢复 |
| 收口旧批次 | 在旧系统提交停止，逐批核对批次结束、尝试停止确认和宿主登记进程组退出；在每台旧设备核对私有状态记录，包含已知的旧根记录和未确认的接受、领取资料 | 未结束批次和未确认尝试为零，关联设备的执行归属明确，未知事实保留并阻断下一步 |
| 建立切换点 | 停止旧 Java 服务及写入同库的后台任务、协作文档进程、队列消费者和直连接口。DBX 核对旧结构、记录数和收口事实，取得同一时间点的可恢复数据库备份与配套配置、应用和执行资料 | 旧库停写有证据，备份在隔离目标恢复成功，旧包和旧结构配对，恢复位置和切换点有记录 |
| 应用结构 | 使用 DBX 先执行 V2 结构增量，再执行 139 删列脚本，逐步回读结构、历史记录和停止事实。应用启动的数据库初始化保持关闭 | 新结构与归档一致，旧四列消失，业务及执行历史保留，DDL 部分成功或不明时停在此处 |
| 同组替换 | 用发布组替换 Java 包及网页，清理网关或浏览器端旧静态资源缓存，授权设备按组升级到 V3.0.1。原 `.env`、`application*`、容器或服务启动配置、挂载、站点地址和凭据来源保留。核对配置与目标数据源之后才启动新服务 | 只存在一组可用协议。旧入口返回升级反馈，新宿主识别协议 2，原设备与绑定可见，协作定时触发关闭 |
| 恢复入口 | 在隔离恢复副本完成获准的启动和连接检查，按切换授权核验目标服务及下载资源。记录新服务首次可能写入的时刻，之后按下表判断回滚边界。经授权后开放网页与执行入口 | 服务、网页、宿主和数据库均指向同一组，恢复入口保留，真实批次和调度各按用户授权执行 |

网页显示停止意图、租约到期、设备离线或旧根记录消失均不足以确认停止。依据旧服务回执、原宿主登记进程组退出和原执行资料核对。同一维护窗口内保护其他项目的数据，结构脚本影响共享库的任务与执行表。

后台宿主保活用于设备服务连接。批次定时触发保持关闭。上线前核验 OAuth 授权和外置 `JWT_SECRET`，版本切换保留原值。发布包依赖外置数据库账号 `MYSQL_USERNAME` 和原数据源设置，交接记录只登记配置键和受控位置。

## 同边界回滚

| 状态 | 回滚动作 | 保护条件 |
| --- | --- | --- |
| 旧字段完整，旧服务尚能使用当前结构 | 维持维护入口，使用原 Java 包、网页、服务配置和兼容宿主恢复旧协议；按旧结构核验后开放 | 前置增量如有执行，先用 DBX 确认原包仍兼容。旧批次的停止事实保留，恢复的是服务能力 |
| 任一旧字段已删除，切换点后业务库无新增写入 | 封闭入口，停稳新服务和宿主，保存当前库、程序和执行证据；将切换前备份恢复到隔离旧结构目标，验证原包和原授权可用后，通过获准的数据源切换恢复旧组 | 原配置文件与证据保留。旧服务只连核对过的旧结构目标，当前库及新协议现场继续保留 |
| 新服务或后台进程存在写入，或写入情况待确认 | 维持维护状态，保留新库与新执行资料，先按当前协议修复；降级前审阅新增业务和执行事实的保全及合并方案，并取得对应授权 | 保留切换前后两套数据及恢复坐标，禁止用旧快照覆盖新事实。网关停流量本身不足以证明停写 |

还原宿主时以原应用、LaunchAgent、站点配置和设备身份为一组，在新宿主受管进程退出后恢复。原安装包和服务配置独立存档，安装器的临时备份不承担此职责。恢复材料存放在受控位置，保留新旧执行记录；设备授权状态按实际原授权核对，钥匙串、令牌与历史回执不写入发布包。项目文件与快照的内容留存用于审计，回滚动作仅处理已授权的服务、数据源和宿主程序。

## 后续授权所需信息

- 目标站点、环境、旧发布标识、当前活动数据源、DBX 连接与库名、实际入口控制方式。
- 获准维护时段、运维负责人与回滚判定人、实际备份及隔离恢复渠道、备份和恢复的目标位置、验收证据保存位置。
- 纳入切换的宿主设备、运行版本、旧批次停止证据来源、新旧安装包及服务器外置配置位置。
- 获准的部署、数据库执行、宿主升级、真实网页或模型验证范围。数据库备份恢复能力、入口控制及停写条件由目标环境证据确认。
