# 痕迹协作 V2 数据库切换材料

本目录是执行材料，未执行数据库操作。使用时须先确认目标环境、数据库和发布授权；本轮不执行脚本。数据库操作通过 DBX 完成。当前项目的 `linear-lite-server/src/main/resources/schema.sql` 是结构依据，不将整个文件作为生产增量执行。

## 目标基线和停点

目标库须具备 `tasks`、项目和用户等现有业务表，OAuth 基础表须与目标服务依赖一致。运行 `00-数据库结构只读预检.sql` 后，按 `schema.sql` 对照协作表的列类型、空值、默认值、排序规则及索引。现存表不匹配时停止，形成单独的修复方案；`CREATE TABLE IF NOT EXISTS` 不会修正已有表。允许以下差异：

- `tasks.input_revision`、`project_device_bindings.revision`、`project_device_bindings.deleted_at` 缺失时由 `02` 增加；字段存在但定义不符时停止。
- 协作新表缺失时由 `02` 创建；表存在时须符合当前定义。旧 `task_execution_attempts.held_write_scopes` 和 `tasks` 的 `write_scopes`、`agent_execution_enabled`、`public_context_refs` 可在 139 脚本前存在，切换后必须不存在。
- OAuth 表不属于 `02` 的建表范围；缺失或定义不符时停止，核对授权部署基线。业务表、字段或索引存在其他差异时停止。

上轮 `20261110-痕迹协作-10ff318` 材料是历史记录，不代表本次目标库状态。其增量会创建 V2 移除的旧字段，不得用于本次切换。

## DBX 执行顺序

1. 在 DBX 选定连接和目标数据库，打开固定会话，执行 `00` 中的 `DATABASE()`、版本及结构查询。每条查询核对行数与截断提示；必要时调整返回上限。使用 `schema.sql` 对照所有已存在的相关表及索引，记录缺表与差异。版本、字符集、排序规则或 JSON 默认值不满足 SQL 的 MySQL 特性时停止。
2. 停止接收协作批次和旧宿主执行，等待旧批次及尝试收口。依据 `00` 的结构结果及旧发布包基线确认缺表原因，按 `01-运行收口只读检查.sql` 逐条查询；缺表有证据时跳过对应查询并记录，已存在表的记录分页核对。`unsettled_batch_count` 与 `unsettled_attempt_count` 须为零。检查每台设备宿主私有状态目录的旧 `roots`、新 `runs`、`attempts`、`process-groups` 记录及登记进程组，核对进程组停止事实；默认目录为用户 `Library/Application Support/Linear-Lite/CodexHost`，实际路径按宿主配置确认。数据库租约过期或查不到表不构成进程停止证据。缺表原因或设备状态不明时停止切换。
3. 在停写窗口通过 DBX 和环境既定的受控备份能力保留目标数据库的结构与全量数据，包含所有业务表、任务及执行历史、绑定、批次、授权、OAuth 状态、索引、约束和触发器。记录备份时间点及关键表行数，在隔离环境验证备份可恢复。备份放在受控位置，不写入仓库、日志或任务材料；授权资料不出现在记录中。DBX 查询的分页结果和行数不等于全量备份。无法取得可恢复备份时停止。
4. 在同一 DBX 固定会话使用 `dbx_execute_batch` 执行 `02-新协议结构增量.sql`，设置 `continue_on_error=false`，不启用事务模式；按语句顺序检查结果。此文件包含会话变量及 `PREPARE`、`EXECUTE`、`DEALLOCATE`，不能拆到不同连接。
5. 第 4 步全部成功后，在同一固定会话按相同方式执行 [139 删除旧协作配置脚本](../20261110-LINEAR-LITE-139-删除旧协作配置.sql)。该脚本删除四个旧字段；字段值与执行证据须已包含在第 3 步备份中。
6. 执行 `04-切换后只读核对.sql`，要求旧字段数和关键缺失字段数均为零；重跑 `00` 对照完整表、字段和索引，重跑 `01` 对照停写前的行数和停止状态。核对前后记录保存到受控位置。仅有行数一致不能证明数据内容一致。

SQL 含 MySQL DDL，DDL 会隐式提交，批处理失败不代表前面的语句被撤销。任一步失败须停止，不执行后续步骤；通过 DBX 重查各表、字段和索引，记录已完成的语句和数据库事实，再确定剩余处理方式。禁止盲目重跑、用旧版本覆盖新结构或自动删除现场证据。

回退须基于切换前的可恢复备份和服务版本，评估切换后产生的数据与设备侧运行事实，选择经授权的恢复操作；本材料不提供自动覆盖生产数据的回滚 SQL。数据库、服务发布包、服务器配置和各设备的项目文件分别保留恢复依据，旧服务与新结构不应混用。
