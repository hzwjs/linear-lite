# Linear Lite UI/UX 设计方案

> 文档状态：当前产品界面的设计基线  
> 适用范围：`src` 下的桌面端与移动端产品界面  
> 事实来源：`PRODUCT.md`、`src/style.css`、`src/mobile/mobile.css` 与现有页面组件

## 1. 设计定位

Linear Lite 是面向项目团队的轻量任务协作工具。界面采用“安静的操作工作台”方向：以任务、文档和项目数据为主体，通过浅色工作区、白色内容面、灰蓝主操作、细分隔线和紧凑系统字体建立层级，不使用营销页式大标题、插画、渐变背景或装饰性卡片。

桌面端与移动端共享项目语义、业务状态和品牌识别，但不共享同一套页面结构：

- **桌面端**承担项目规划和完整管理，强调信息密度、横向比较、键盘效率和多视图切换。
- **移动端**承担短时查看和高频执行，强调单手操作、短路径、全屏推进和触控反馈。
- **项目是一级上下文**。移动端默认“只看我的任务”，但不引入个人日程或独立的每日任务模型。

### 核心原则

1. **内容先于容器**：任务、字段、评论和文档正文是主角，容器只负责组织信息。
2. **结构先于装饰**：通过留白、细线、字号和表面层级表达关系，避免依赖阴影和大面积色块。
3. **主操作克制且明确**：灰蓝强调色只用于主按钮、选中态、链接和焦点，不扩散到普通信息面。
4. **状态必须可行动**：加载、空态、失败、保存中、禁用和冲突均提供明确反馈及恢复动作。
5. **两端各自符合设备心智**：桌面保留侧栏、工具栏和密集列表；移动采用底部导航、底部面板和全屏详情。
6. **稳定内容结构**：异步加载不改写已保存内容的语义结构，加载反馈附着于表现层；临时内容才使用占位结构。

## 2. 信息架构

### 2.1 自适应分流

`AdaptiveRoot.vue` 使用唯一断点选择应用壳层：

- `>= 1100px`：桌面应用 `App.vue`。
- `< 1100px`：移动应用 `MobileApp.vue`。

这不是同一页面的压缩布局，而是共用路由、Pinia 和 API 的两套交互结构。不得在桌面页面上叠加移动补丁，也不得把桌面看板直接缩放到移动端。

### 2.2 桌面端结构

桌面端采用固定侧栏加弹性主工作区：

- **全局侧栏**：宽 240px，承载账户、全局搜索、收藏、Analytics、项目列表和项目内任务/文档入口；可隐藏并从屏幕边缘恢复。
- **任务工作区**：顶部命令栏负责范围、搜索、筛选、显示配置和视图切换；主体支持看板、列表和甘特图。
- **任务详情**：使用可深链的内联全高编辑工作区，保留上一个/下一个任务导航；打开详情后隐藏无关命令栏。
- **任务创建**：使用集中式 Composer；从分组或列头进入时预填对应状态，从父任务进入时建立子任务上下文。
- **文档工作区**：项目文档树与正文编辑器并列；搜索、历史、归档、收藏和冲突处理在当前工作区完成。
- **Analytics**：按“健康结论 -> 指标证据 -> 交付节奏 -> 风险归属 -> 行动任务”组织，不做等权图表墙。
- **项目设置**：使用独立设置路由与左侧分区导航，避免在弹窗中承载长流程。
- **认证页**：登录、注册和重置密码共用单一表单容器，错误贴近当前操作呈现。

### 2.3 移动端结构

移动端壳层最大宽度 720px，在平板窄视口中居中显示：

- **任务首页**：项目切换和账户入口位于顶部；随后是搜索、筛选摘要和按状态分组的任务列表。
- **默认范围**：默认仅显示分配给当前用户的任务，可在筛选底部面板切换为当前项目全部任务。
- **底部导航**：任务、搜索、居中的新建任务、通知共四个位置；新建按钮是唯一悬浮主操作。
- **任务创建**：全屏表单，标题和描述优先，状态、优先级、负责人和截止日期作为第二层属性。
- **任务详情**：全屏推进；首屏展示项目、状态、优先级、标题和描述，属性集中在底部面板编辑，随后按子任务、附件、评论排列。
- **通知**：独立列表页签，点击通知直接进入任务深链。
- **文档**：移动端提供只读正文、收藏和返回；完整编辑仍由桌面端承担。
- **底部面板**：用于项目切换、账户、筛选和属性编辑，包含遮罩、焦点圈定、Esc 关闭和焦点归还。

移动端不展示看板、甘特图、Analytics、批量操作、拖拽排序、显示配置、项目管理和任务导入。

## 3. 视觉系统

### 3.1 色彩

#### 桌面端基础色

| 角色 | 令牌 | 值 | 用途 |
|---|---|---:|---|
| 主内容面 | `--color-bg-base` | `#ffffff` | 页面、列表、编辑器 |
| 次级背景 | `--color-bg-subtle` | `#fafafa` | 工作区、侧栏层次 |
| 弱背景 | `--color-bg-muted` | `#f5f5f5` | 标签、计数、禁用面 |
| 悬停背景 | `--color-bg-hover` | `#f0f0f0` | 行、按钮、导航悬停 |
| 激活背景 | `--color-bg-active` | `#ebebeb` | 按下和明确选中 |
| 主文字 | `--color-text-primary` | `#0d0d0d` | 标题、任务名、主要数据 |
| 次文字 | `--color-text-secondary` | `#5e5e5e` | 描述、字段值、辅助说明 |
| 弱文字 | `--color-text-muted` | `#7a7a7a` | 元数据、占位、低优先信息 |
| 主强调 | `--color-accent` | `#475569` | 主操作、选中、焦点、链接 |
| 强调悬停 | `--color-accent-hover` | `#334155` | 主操作悬停和按下 |
| 默认边线 | `--color-border` | `#e8e8e8` | 容器、输入框、分区 |
| 弱边线 | `--color-border-subtle` | `#f0f0f0` | 列表行和低层级分隔 |
| 强边线 | `--color-border-strong` | `#dddddd` | 焦点和强调边界 |

#### 语义色

- 完成/稳定：灰蓝或深绿，仅用于完成状态和成功反馈。
- 进行中/信息：蓝色，仅用于状态图形或信息提示。
- 待评审/临期：低饱和金色，仅用于警示和日期语义。
- 失败/逾期/破坏性操作：克制红色 `#c94a4a`。
- 标签色板仅用于标签语义点，不作为普通按钮或页面装饰。
- 任何状态均不能只靠颜色表达，必须同时提供图形、文本或位置线索。

#### 移动端表面

移动端在同一品牌方向下提高空间感和触控辨识度：

- 画布 `#f4f5f6`，主表面 `#ffffff`，弱表面 `#f8f8f9`。
- 主文字 `#111214`，次文字 `#565b63`，弱文字 `#666c75`。
- 主强调保持 `#475569`，确保跨端身份一致。
- 任务组、通知组和表单属性组使用白色表面与 `#e6e7e9` 细边线。
- 移动底部导航可使用轻微半透明和模糊，但只作为固定导航层，不扩散为全局玻璃效果。

### 3.2 字体与信息层级

全局字体为 `Inter`，回退到 Apple/Windows 系统无衬线字体；中文详情补充 `PingFang SC`、`Hiragino Sans GB` 和 `Microsoft YaHei`。数字、日期和计数使用等宽数字特性以减少跳动。

#### 桌面端字号

| 层级 | 尺寸 | 字重 | 用途 |
|---|---:|---:|---|
| 辅助标签 | 11px | 400-500 | 快捷键、紧凑元信息 |
| 说明文字 | 12px | 400-500 | 字段标签、计数、时间 |
| 正文/控件 | 13px | 400-500 | 列表、按钮、输入、导航 |
| 次标题 | 14px | 500-600 | 分组标题、弹层标题 |
| 页面标题 | 20-28px | 600-650 | Analytics 结论、编辑页标题 |

桌面默认保持紧凑，不使用营销页级大字号。任务标题和文档标题可以放大，但不能挤压操作区或造成横向滚动。

#### 移动端字号

- 正文和输入：15-16px，保证手持阅读并避免浏览器输入缩放。
- 任务标题：16px；任务编号和日期：12-13px。
- 分组标题：16px；页面标题：19-30px。
- 任务详情标题：26-29px；正文 16px、行高约 1.7，优先保证连续阅读。
- 文本默认允许换行；仅任务列表标题、导航标题和受限元数据可单行截断。

### 3.3 间距、形状和深度

- 桌面端以 4px 为基础节奏，常用间距为 4、8、12、16、24px。
- 移动端页面水平内边距为 `clamp(16px, 4.6vw, 22px)`，控件间距通常为 8-13px。
- 桌面圆角保持克制：3、4、5、6px；强调精密、紧凑和工具属性。
- 移动控件圆角 10-12px，分组容器 13-15px，底部面板顶部圆角 18px；圆角服务于触控分组，不演变为大量独立卡片。
- 桌面表面默认无阴影，以背景和边线分层；弹层使用 `0 4px 12px rgba(0,0,0,.08)`。
- 移动阴影只用于固定导航、空态图形、悬浮新建按钮和底部面板等确有层级的对象。
- 页面区段保持无框；卡片仅用于任务组、重复列表项、弹层和真正需要边界的工具。

## 4. 核心组件规范

### 4.1 按钮与图标

- 使用 `lucide-vue-next` 图标；已有优先级图形继续使用项目自定义图标组件。
- 图标按钮用于返回、关闭、收藏、搜索、筛选、设置和新增等熟悉动作，并提供 `aria-label` 或 tooltip。
- 桌面普通控件默认最小高度 28px，主要面向精确鼠标和键盘操作。
- 移动端所有核心触控目标至少 44x44px；列表行通常为 54-76px。
- 主按钮使用灰蓝底和白字；次按钮使用白底、细边框和主文字；破坏性按钮使用红色文字与浅红边界。
- 加载中的按钮禁用重复提交，并在原位置显示 spinner 或进行中文案，保持布局尺寸稳定。

### 4.2 输入与筛选

- 输入必须有可感知标签；占位符只能补充示例，不能替代标签。
- 桌面筛选支持弹出菜单、组合框和多选；活动筛选以摘要或计数显示，并提供一键清除。
- 移动筛选使用“当前范围 · 状态摘要”单入口，具体选项放入底部面板，避免首页堆叠筛选控件。
- 焦点通过边线变化和 2px 轮廓表达，不移除浏览器键盘焦点能力。
- 表单错误贴近当前表单或操作呈现，并保留用户已输入内容。

### 4.3 列表、任务行与分组

- 桌面列表以细分隔线和列对齐承载高密度字段；hover 仅提升当前行，不改变行高。
- 看板列并排呈现，列间使用边线；卡片不使用厚重阴影。
- 移动任务按状态分组，每组可折叠；任务行依次强调状态、标题、任务编号、负责人、优先级和截止时间。
- 逾期时间使用红色，同时保留日期和日历图标。
- 动态标签、计数、加载图标和 hover 状态不得改变行高或列宽。

### 4.4 弹层与底部面板

- 桌面命令面板、搜索、Composer 和设置弹层使用统一 overlay 栈；Esc 只关闭最上层浮层。
- 对话框包含语义角色、名称、初始焦点和关闭入口；关闭后焦点返回触发控件。
- 移动底部面板从底部进入，背景遮罩约 42%；焦点被限制在面板内，页面背景设为 inert，关闭时恢复焦点和页面滚动。
- 有未保存内容的创建流程在返回、浏览器后退或离开前确认，避免静默丢失。

### 4.5 空态、加载和错误

- **初次加载**：使用固定尺寸骨架或局部 spinner，不让已有内容闪退为空。
- **刷新加载**：保留已加载内容，局部展示刷新状态。
- **业务空态**：说明当前范围为何为空，并给出“新建任务”“查看全部任务”等直接动作。
- **筛选空态**：明确是搜索或筛选导致，主动作是清除条件。
- **错误态**：说明失败对象，提供原地重试；表单与编辑内容不得被清空。
- **保存态**：显示保存中、已保存、冲突或失败；文档冲突提供重新加载或重试，不做静默覆盖。

## 5. 关键用户流程

### 5.1 桌面任务处理

1. 在侧栏选择项目。
2. 在命令栏选择任务范围、搜索或筛选。
3. 以列表、看板或甘特图查看任务。
4. 点击任务进入可深链的详情工作区。
5. 编辑字段、正文、子任务、附件和评论；自动保存或显式提交后保持上下文。
6. 关闭详情回到原任务视图和筛选状态。

桌面效率入口包括 `Cmd/Ctrl + K` 全局搜索、`C` 新建任务、`Esc` 关闭顶层浮层，以及列表中的方向键选择和 Enter 打开。

### 5.2 移动任务处理

1. 在顶部确认或切换项目。
2. 默认查看“我的任务”，按需搜索或打开筛选面板。
3. 从状态分组中打开任务，或点击底部中央按钮新建任务。
4. 在全屏详情中阅读任务；点击信息摘要后从底部面板修改属性。
5. 继续处理子任务、附件和评论；完成后通过返回恢复前一上下文。

移动主路径不得要求横向滚动、缩放页面或理解桌面列结构。

### 5.3 文档处理

- 桌面端使用项目文档树定位文档，在同一工作区完成编辑、搜索、历史、归档和冲突处理。
- 移动端由收藏或深链进入只读文档，展示项目上下文、标题、正文和收藏动作。
- 文档异步资源的加载反馈不得改变已保存正文的 DOM 结构和排版关系。

## 6. Analytics 设计

Analytics 是项目复盘工具，不是通用 BI 仪表盘：

- 首屏先给出当前周期的项目健康结论，而不是先展示图表。
- 逾期、完成、创建和到期四项指标组成可下钻证据带，点击后更新行动任务列表。
- 趋势图回答“交付节奏是否健康”；状态和负责人分布回答“风险在哪里”。
- 语义色仅用于健康、注意和严重状态，图表同时提供标签、数值和列表入口。
- 内容最大宽度约 1240px，页面区段使用边线和留白分隔，不将每张图都包装为浮动卡片。

## 7. 响应式与无障碍约束

### 响应式

- 320-1099px 进入移动应用；1100px 起进入桌面应用。
- 移动壳层最大宽度 720px；721-1099px 居中显示，保持移动信息架构而非拉伸为桌面布局。
- 360px 以下收紧任务行网格并隐藏低优先级头像信息，保留标题、状态和截止日期。
- 使用 `100dvh`、安全区变量和固定底部导航预留，避免浏览器工具栏、刘海和 Home Indicator 遮挡内容。
- 任何 320-1024px 视口不得产生页面级横向滚动；代码块等局部内容可在自身容器滚动。

### 无障碍

- 文字与背景对比度遵循正文至少 4.5:1，大字至少 3:1。
- 所有核心流程可通过键盘完成；不得移除 `focus-visible`。
- 图标按钮必须有可访问名称，状态图形设为装饰时使用 `aria-hidden`。
- Dialog、alert、status、busy、pressed 和 expanded 状态使用对应语义属性。
- 移动核心触控区域至少 44x44px，交互项间保持可辨认间距。
- 底部面板和对话框需要焦点圈定、背景隔离、Esc 关闭和焦点归还。
- 尊重 `prefers-reduced-motion`：关闭非必要动画，保留即时状态变化。
- 中文正文不低于 15px；系统缩放后文本可换行，不遮挡前后内容。

## 8. 动效与反馈

- 桌面交互状态使用 120ms 快速过渡，普通视图切换约 150-180ms。
- 移动状态过渡约 160-180ms；底部面板位移约 240ms，使用减速曲线表达进入和退出层级。
- 动效只用于说明状态、空间关系和操作结果，不做持续装饰。
- hover、active、loading 和 selected 状态必须保持控件尺寸稳定。
- 触控按下可使用轻微背景变化或小幅缩放反馈；不得让文本或相邻控件位移。
- 减少动态效果模式下，将动画和过渡缩短到近乎即时。

## 9. 内容与文案

- 同一对象使用同一术语；界面统一使用“任务”，避免在同一路径混用 task、issue 和事项。
- 按钮使用明确动词，如“创建任务”“清除筛选”“重新加载”“保存内容”。
- 错误文案说明失败对象与下一步，不直接展示无法指导行动的 HTTP 状态文本。
- 空态文案区分业务无数据、当前用户无任务、搜索无结果和筛选无结果。
- 破坏性操作在执行前说明对象；可恢复操作优先提供撤销，无法恢复时使用确认。
- 中英文通过现有 `vue-i18n` 体系管理，不在共享桌面组件中新增硬编码文案。

## 10. 实施约束

1. 新界面优先复用 `src/style.css` 的桌面语义令牌或 `src/mobile/mobile.css` 的移动令牌，不在组件内复制同义颜色、圆角和字号。
2. 视觉值按“全局令牌 -> 组件度量 -> 页面布局度量”分层；页面模板中不散落重复的裸值。
3. 新增视觉角色时扩展现有组件 variant；只有结构或行为显著不同才创建新组件。
4. 固定格式元素使用稳定尺寸、网格轨道或 `minmax()` 约束，动态数据不得引发布局跳动。
5. 页面区段使用无框布局；禁止卡片嵌套卡片，禁止用装饰卡片代替信息层级。
6. 图标优先使用 Lucide，不手绘重复 SVG，不用 emoji 充当功能图标。
7. 桌面与移动只共享业务数据、路由语义和可复用逻辑，不强行共享页面级布局组件。
8. 新增页面必须具备加载、空态、失败、禁用和成功反馈，不以静默失败或控制台日志代替用户反馈。
9. 新增移动界面必须处理安全区、虚拟键盘、浏览器后退和未保存内容。
10. 新增桌面界面必须支持合理的键盘导航、焦点恢复和顶层 Esc 关闭规则。

## 11. 当前边界与事实来源

根目录 `DESIGN.md` 当前描述的是 Linear 营销站的暗色视觉体系，与本项目已实现的浅色产品工作台不一致。产品界面的实施优先级如下：

1. `src/style.css` 与 `src/mobile/mobile.css` 中的实际语义令牌。
2. 已投产的共享组件和页面交互模式。
3. 本文档对跨页面 UI/UX 规则的归纳。
4. `PRODUCT.md` 中的产品定位、端能力边界和无障碍承诺。

在根 `DESIGN.md` 被重新提取为产品界面设计系统前，不得将其中的近黑画布、营销页大字号、暗色卡片或产品截图主导规则应用到 Linear Lite 工作台。
