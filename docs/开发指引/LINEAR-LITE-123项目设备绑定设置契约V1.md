# LINEAR-LITE-123 项目设备绑定设置契约 V1

## 数据与设备

项目设置中的“项目目录绑定”使用认证用户、当前项目和宿主提供的稳定 `deviceId`。服务端 `POST /api/collaboration/bindings/list` 返回 `{bindings}`，每条记录包含 `id`、`userId`、`projectId`、`deviceId`、`projectDirectory`、`revision`、`createdAt` 与 `updatedAt`。前端使用这些字段，用户身份由服务端认证上下文确定，请求不携带 `userId`。

当前设备身份来自本机宿主 `GET http://127.0.0.1:9781/identity`，响应字段为 `deviceId` 和 `hostInstanceId`。服务端列表是绑定事实来源，前端不使用浏览器生成的设备标识或 Pi 项目目录作为替代。刷新或项目、认证用户变化后，界面重新读取宿主身份和该用户在项目中的绑定。

设备选择器展示本机设备与同用户该项目下的其他设备；默认选择本机设备。其他设备的目录可以查看，目录和删除操作在对应宿主设备上进行。本机宿主不可用时，用户仍可查看返回的绑定，写操作保持不可用。

## 目录保存与删除

项目根目录是绑定中唯一可维护的目录。用户输入本机项目绝对路径，保存前调用宿主 `POST /validate-directory`，传入当前 `deviceId` 和 `projectDirectory`；宿主检查设备、目录及物理路径，并返回规范化的 `projectDirectory`。前端确认返回的设备匹配，使用返回的路径调用服务端保存接口。宿主拒绝目录或设备不匹配时，不调用保存接口。

协作资料目录从界面中的项目根目录派生 `docs`，不提供第二个目录输入或存储字段。macOS/Linux 路径使用 `/`，Windows 驱动器和 UNC 路径使用对应分隔符；服务端保存后的目录由绑定响应返回并用于显示。

删除仅面向当前宿主设备的绑定，并使用现有项目设置的确认交互。删除前重新读取宿主设备身份；身份变化时不调用删除接口。服务端对尚未确认停止的执行返回冲突，界面展示服务端的等待停止原因，保留当前显示的绑定。用户可通过刷新重新读取绑定列表；删除失败不会在前端移除记录。保存遇到相同冲突时采用相同错误反馈。

加载绑定失败时禁止写入，界面展示权限或请求错误；项目切换期间的旧响应不会覆盖新项目数据，也不会在宿主目录校验完成后向旧项目发送保存请求。页面没有复制协作任务状态或领取权。

## 验证范围

七个定向前端测试文件按各文件最后一次结果共 29 项通过：覆盖设备选择、跨设备只读、目录规范化保存、缺失目录、设备失配、权限失败、执行占用时的保存/删除反馈、项目切换竞态、`docs` 派生（含 POSIX 名称尾部反斜线）、项目设置入口及现有本地执行和远程终端设置回归。测试通过 mock 宿主与后端接口验证组件和客户端契约，非部署运行证明。

`vue-tsc -b --pretty false` 通过；Vite 生产构建输出到独立临时目录并通过，临时目录清理。浏览器 E2E 与真实宿主部署运行不属于本轮验证范围。
