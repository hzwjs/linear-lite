# LINEAR-LITE-141 成果驱动关系契约 V1

关系维护以当前执行尝试为入口，复用批次、项目、设备、领取凭据、输入版本和租约校验。业务调用使用 `change_collaboration_dependency`；项目协调事务覆盖关系检查、事实记录、版本变化和停止意图。

`change` 包含 `action`、`prerequisiteTaskId`、`missing`、`reason`、`evidence`、`goal`、`impact`。`ADD` 和 `REMOVE` 使用来源任务标识，并提供缺少的成果、判断原因和依据。`REQUEST_GOAL` 表达超出当前业务目标的新增需求，不指定任务，提供目标、影响和依据；用户无需填写关系或任务编号。

已有同项目、同绑定、当前输入版本、确认停止的成功成果可作为关系来源。来源位于批次外且没有有效成果时，响应 `MISSING_OUTSIDE_BATCH`、缺少的成果、目标、影响及处理方式：当前目标内由 Agent 在本任务解决；新增业务目标经授权后进入新批次。`REQUEST_GOAL` 返回 `GOAL_AUTHORIZATION_REQUIRED` 并提交当前尝试停止意图，不创建任务或扩张原批次集合。

建立和撤销检查同项目、叶子节点、自依赖与循环；关系语义变化使当前任务和下游输入版本递增并请求停止旧尝试。宿主确认停止后，领取流程按新版本和成果条件判断。重复关系不递增版本；相同操作标识按原请求回放，复用标识提交不同请求会冲突。

关系判断有误且前置成果缺失时，原尝试确认停止、仍为该任务最新尝试且没有其他未确认尝试，并持有有效批次授权时，可以按关系建立后的输入版本撤销该尝试建立且仍存在的关系；业务输入变化或关系经过其他尝试撤销、重建后不能使用此入口。宿主在 LINEAR-LITE-146 接入该收回操作，停止确认后的模型会话不再运行；该入口不授予新增关系、申请目标或修改项目文件的权利。

新增业务目标的授权等待记录约束原批次同一输入版本的领取；用户授权新目标后由新批次处理，业务输入版本变化后旧等待事实不再阻塞。

操作事实写入执行检查点与既有操作回执，包含来源尝试、操作者、原因和依据；环境查询按项目与任务投影业务字段，领取凭据和批次令牌不进入事实。任务本身不预配置前置关系。

本任务复用 `task_dependencies`、`task_execution_attempts` 和 `task_execution_operations`，无数据库结构修改或 SQL 执行；宿主工具接线由 LINEAR-LITE-146 负责，本卡协议检查不等同真实模型联调。
