# LINEAR-LITE-116 痕迹协作输入与依赖契约 V1

任务保存执行授权、计划写入范围、输入版本和公共约定引用。公共约定引用使用 `publicContextRefs`，每项包含 `documentId` 和 `version`；任务列表与任务详情使用同一数据路径。项目、用户、设备的绑定记录由 LINEAR-LITE-115 管理。

## 输入修改

`TaskCollaborationInputService.replaceInputs` 接收任务标识、当前输入版本、执行授权、写入范围、公共约定引用和前置任务 ID。服务检查项目成员权限、项目锁和版本；过期版本拒绝写入。写入范围使用项目根目录下的规范相对路径，目录以 `/` 结尾；路径别名和重复范围拒绝写入。公共约定必须属于同一项目、处于可用状态且版本匹配。

前置任务必须属于同一项目，依赖两端均为叶子任务；自依赖、重复边与环拒绝写入。建立协作依赖或开启授权后，修改任务输入会递增当前任务及下游任务的输入版本，使已完成任务回到待办，并向尚未确认停止的执行发出停止意图。共同下游在一次变更中只递增一次。没有授权、公共引用、依赖边和执行历史的人工任务编辑保留完成状态；仅修改此类任务的协作草稿范围时，输入版本递增但完成状态保留。

## 痕迹与失效

普通任务更新、文档版本提交、版本恢复、标题变更和归档状态变更在业务事务内发布协作事件。可用文档版本变化推进引用版本；归档保留引用定位并使旧成果失效。取消任务、关闭授权或删除项目会请求停止相关执行，冻结的写入范围保留至执行宿主确认停止。项目删除在独立事务提交停止意图；存在待确认执行时返回冲突，停止确认后才能删除项目与项目内协作记录。

## 后续服务调用边界

`requireCurrentInputs` 供交付入口在项目事务中调用：检查输入版本、叶子任务、公共约定版本和同一设备绑定下前置任务的有效成功成果。领取、执行生命周期、成果提交及面向客户端的协作接口由后续任务实现；本契约不提供调度或执行能力。
