# LINEAR-LITE-119 成果交付与完成门禁契约 V1

## 完成命令

`TaskCollaborationCompletionService.complete` 接收认证用户、批次上下文、任务 ID、执行命令、交付证据和宿主停止确认。执行命令包含执行尝试、领取标识、输入版本、宿主实例、Agent 实例与操作标识。

`TaskDeliveryEvidence` 包含完成条件列表、修改位置、产物引用和项目稳定检查点。每条完成条件包含条件文本、结果与证据引用；完成条件、结果、证据引用、产物引用及项目检查点不能为空。修改位置使用项目相对路径；只读任务允许空列表，其他路径须位于尝试持有范围之内。服务不检查宿主文件系统，产物存在性及稳定检查点由宿主核验。

宿主停止确认须表明执行单元与关联写入进程停止，并提供停止事实。服务核验该声明的格式，无法代替宿主检查本机进程。

## 版本与事务

完成命令采用 READ_COMMITTED 事务，批次授权取得项目协调锁，执行归属校验覆盖认证用户、批次、绑定、任务、尝试、实例及领取标识。来源版本从服务端现有事实读取：任务输入版本来自尝试的 `inputRevision`，前置成果版本来自尝试的 `prerequisiteVersions`，公共约定版本来自任务的 `publicContextRefs`。请求中的输入版本须与尝试和当前任务匹配，前置成果须与领取快照及当前有效成果一致。

归属校验后读取幂等回执；相同请求返回原结果，不重复保存证据或推进状态。相同操作标识用于不同请求时返回冲突。新请求校验有效租约、输入、前置成果与任务状态；出现租约过期或当前输入失效时记录停止意图并返回结构化拒绝结果，调用方在事务提交后映射错误，保留停止事实和范围冻结。

成功时，服务在同一项目协调事务内保存执行尝试的 `succeeded`、交付证据、停止确认和完成时间；调用任务状态服务设置 `done` 与进度 100；计算可完成的父卡；保存无凭据操作回执。停止确认时间解除范围占用，历史持有范围保留。异常导致同一事务中的尝试、状态及回执回滚。

完成条件、结果、引用、检查点、停止事实及操作标识不得包含本次批次或领取凭据；服务检查本次请求携带的凭据，拒绝包含这些凭据的业务材料。授权材料不进入交付证据、操作回执或执行记录响应。

## 统一完成门禁

`TaskStatusService.updateState` 是现有任务状态、进度及完成时间的写入入口。任务参与协作时，进入 `done` 须存在同任务、当前输入版本的成功尝试，尝试具有非空结果证据及停止确认。参与协作沿用输入失效的判定：启用协作、存在公共约定引用、任一方向的前置依赖或历史执行尝试。关闭授权不会删除参与历史或绕过证据门禁。

普通任务更新、进度 100% 和层级汇总经此入口；协作父卡不因子卡终态汇总进入 `done`，父卡汇总不构成前置成功证明。没有协作授权、公共引用、依赖及执行历史的人工任务保持现有完成行为。导入只创建人工任务；导入后的父卡汇总使用相同门禁。

普通更新撤销 `done` 时发布输入失效事件，当前任务与受影响下游递增输入版本；旧版本交付结果无法通过完成门禁。完成与输入变更使用相同项目锁，状态与来源版本保持事务顺序。

## 接口层调用

成功或拒绝结果由 `Result(accepted, reason, data)` 表达。成功 `data` 包含 `attemptId`、`taskId`、`status`、`inputRevision`、`evidence`、`stopConfirmedAt` 和 `ancestorChanges`；拒绝 `data` 包含原因。REST 与 MCP 使用同一领域服务，禁止在入口复制完成判断或另建完成状态。
