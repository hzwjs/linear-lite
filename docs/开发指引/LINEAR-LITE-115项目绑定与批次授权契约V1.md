# LINEAR-LITE-115 项目绑定与批次授权契约 V1

本契约覆盖本机项目绑定和批次授权服务。领取、检查点、续租、交付、停止恢复及 REST/MCP 接入由后续任务实现。

## 1. 绑定身份与目录

`project_device_bindings` 的 `(user_id, project_id, device_id)` 为唯一身份。服务接收的用户标识来自调用方认证上下文，项目成员资格在项目行锁后校验。设备标识由宿主持久保存；主机名和 IP 地址禁止替代设备身份。

`project_directory` 是绑定中的项目根目录，`docs/` 由宿主从根目录派生。服务端检查绝对路径声明和可检查的规范化语法；设备目录、符号链接和文件存在性由执行宿主核实，服务端禁止通过其本机文件系统推断远端设备目录。

绑定服务提供保存、读取和删除操作：

- 新绑定以版本 `1` 保存；重复保存相同目录保持版本和记录标识。
- 目录变更、逻辑删除及恢复各递增一次 `revision`。
- 删除保留原记录及执行尝试归属；恢复复用同一记录标识。
- 执行尝试缺少 `stop_confirmed_at` 时，目录变更、删除和恢复遭拒；租约时间、失败状态及信号发送缺少停止证明。
- 项目目录声明或设备不匹配时，批次绑定检查遭拒。现有 Pi 人工 turn 的目录配置禁止充当协作目录的备用来源。

## 2. 固定批次授权

`CollaborationBatchAuthorizationService.issue` 接收认证用户、项目、绑定标识、设备、宿主确认的项目目录、任务数据库标识列表和有效期。服务在同一项目协调事务中验证项目成员、绑定归属及任务项目，生成批次标识并签发上下文。

签名上下文包含固定用途、签发方、接收方、批次、用户、项目、绑定、绑定版本、设备、任务范围和有效期。绑定目录保持绑定记录的事实来源，目录字段排除在令牌之外。

批次授权校验签名、用途、签发方、接收方、有效期、认证用户、绑定、设备、目录、任务范围和项目成员资格；服务读取当前绑定版本，在任务操作时读取目标任务的项目归属。绑定版本变化、逻辑删除、过期、设备错配、目录错配、任务移出授权范围或项目时，校验遭拒。

`observeBatch` 授权观察签名上下文中的任务范围；`authorizeTask` 要求目标任务标识，供领取和回写服务调用。返回的 `BatchContext` 包含经过校验的批次与范围信息，令牌原文排除在返回内容之外。

批次用途使用固定非数字 subject 与登录令牌区分，校验签发方、接收方和用途。签名沿用项目 JWT 密钥配置，错误响应使用固定文案；签发结果的 `toString` 遮蔽授权材料。令牌、令牌声明和密钥禁止进入日志、项目文档、评论或检查点。

## 3. 事务与调用边界

绑定保存、读取、删除及批次签发/校验使用 `READ_COMMITTED` 事务，按项目行 → 绑定行 → 执行尝试检查的顺序协调。项目成员资格在项目行锁之后检查。

后续领取、续租、检查点和交付服务需在同一 `READ_COMMITTED` 事务中调用批次校验，并在事务内检查任务版本、尝试归属、租约、领取标识及停止状态；批次上下文的 `batchId` 与执行尝试的 `batch_id` 需要一致。停止确认属于恢复操作，需要保持过期尝试的可处理路径，禁止恢复过期业务写入权。

批次授权限定固定绑定与任务范围，缺少本机设备认证、文件系统强制隔离及进程退出证明。设备标识的可信承载、同根目录互斥、续租和停止覆盖属于 LINEAR-LITE-122 的宿主集成职责。

项目成员撤销需要使用相同项目协调锁。成员资格失效后，批次校验遭拒；活动尝试的停止意图与资源冻结由任务输入与执行生命周期服务承担。
