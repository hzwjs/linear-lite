# LINEAR-LITE-118 执行生命周期契约 V1

## 业务写入

`TaskExecutionLifecycleService` 提供 `renew` 和 `checkpoint`。调用方传入认证用户、批次上下文、任务 ID 和执行命令；执行命令包含尝试、领取标识、输入版本、宿主实例、Agent 实例和操作标识。批次和领取标识不进入操作回执或检查点。

业务操作使用 READ_COMMITTED 项目协调事务。`TaskExecutionAccessService.requireOwnedAttempt` 校验批次、任务、绑定、实例与领取标识；匹配请求的操作回执返回原结果，否则 `checkWritable` 校验停止状态、真实租约、任务输入和前置成果快照。新请求的输入版本错误时拒绝写入；真实租约过期、输入失效或前置成果失效时记录停止意图并保留范围。业务拒绝通过结果对象返回，调用方在事务提交后转换错误响应，禁止以事务内异常撤销停止意图。

前置成果沿领取时 `prerequisiteVersions` 的任务 ID、尝试 ID 与输入版本核验，项目锁内复用输入评估。成功尝试、绑定、停止确认、成果及公共约定版本不满足时请求停止；持有范围在确认停止前冻结。

续租以服务端时间更新五分钟租约，不追加检查点。检查点记录操作标识、执行者、发生时间、发现、成果引用及阻塞原因，按执行记录中的数组顺序追加；重放返回原序号与原事实，重放不追加记录。同一操作标识用于不同请求时，操作回执服务返回冲突。

## 停止与恢复

`requestStop` 和 `confirmStop` 为独立恢复入口，使用认证用户、项目、绑定、设备、任务、尝试、宿主实例、Agent 实例及领取标识核对归属。项目行、绑定、任务和尝试按顺序加锁。操作不要求有效批次、租约、输入版本或当前项目成员资格，也不恢复业务写入权。

停止请求保存首个停止原因；后续停止请求的原因保存在各自操作回执。租约过期的尝试允许在确认时补记停止意图。确认请求包含宿主对进程停止的事实；服务记录停止确认时间与事实，保留持有范围快照，资源占用由 `stopConfirmedAt` 判断。确认、状态处理与回执写入处于同一项目协调事务。

确认时 `done`、`canceled`、`duplicate` 保留原值；授权关闭或绑定用户不再是项目成员时保留原状态；具有授权和成员资格的非终态任务回到 `todo`、进度归零。对已有停止确认的旧尝试使用新操作标识重复确认时返回该尝试的停止事实，不改任务与后续尝试；相同操作标识返回原回执。

宿主负责停止执行单元及关联写入进程，停止事实由宿主声明；服务端没有操作系统进程控制能力。宿主、REST/MCP 和成果交付接入由后续任务承担。
