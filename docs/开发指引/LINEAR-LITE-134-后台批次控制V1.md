# LINEAR-LITE-134 后台批次控制 V1

## 领取与执行

宿主按五秒间隔通过授权接口查询待领取批次。浏览器不参与运行链路。宿主按批次和项目目录限制并发执行池，同批次重复查询不会创建第二个池；不同项目目录可执行各自批次。物理根目录锁继续约束真实目录，接受失败或结果不明时保留恢复事实。

执行池读取服务端批次上下文，使用其中的并发、固定截止时间和 `attemptsUsed`。任务及写入许可、依赖、检查点、成果和停止事实沿用服务端领域数据。依赖或资源等待时保留批次，周期观察；无就绪任务不视为完成，也不重设预算。

## 停止与恢复

停止意图、生存期结束或宿主关闭时，执行池阻止新领取，封存并排空写入门禁，请求停止；受管 Codex 回合和登记的进程组结束后提交停止确认。全部尝试确认后结束批次，再释放根锁和原批次凭据。进程退出、服务确认或凭据状态不明时，保留目录锁与恢复资料。

每个执行槽位在创建 Codex app-server 进程前保存进程组关联。`starting` 表示创建结果未知，`running` 记录进程组，`idle` 表示该组退出。配置发现进程组退出后，才创建执行进程组。日志不保存令牌、任务内容或检查点。

后台启动及轮询时扫描本机根锁。原宿主退出后，检查执行日志与进程组关联；同一宿主网络恢复时，执行池交付绑定原根锁归属的内存证明，证明各槽位、工具队列和写入门禁均已结束，驱动等待执行池返回后才尝试恢复。根锁归属变化、槽位未结束、写入门禁未排空、登记组存活、创建结果未知、关联缺失或检查失败时保持冻结，不对归属不明的进程发送信号。

核实停止后使用原批次凭据经停止专用接口逐项确认和结束，释放目录锁后删除凭据。该恢复流程不依赖新待领取批次或当前 OAuth 授权，不重新接受旧批次。接受结果未知或缺少原批次凭据时保留根锁。

受管进程证明覆盖登记的 app-server 进程组与宿主写入门禁；它不证明脱离该进程组的任意外部进程状态。

## 状态与边界

服务器从持久批次、任务、尝试和停止事实提供批次状态；宿主不建立第二份业务状态或检查点副本。浏览器关闭不影响后台服务。电脑关机、睡眠或网络中断后，失联执行按停止恢复处理，不能根据租约超时推断旧进程退出。

本功能不启用定时任务。安装服务、项目目录绑定、批次网页和部署分别遵循对应任务及交付说明。
