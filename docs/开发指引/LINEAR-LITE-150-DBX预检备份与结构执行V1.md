## 固定会话与失败处理

获得授权后在 DBX 选择已核对的连接和数据库，用 `dbx_open_session` 打开固定会话。02 和 03 的每段 `SET`、`PREPARE`、`EXECUTE`、`DEALLOCATE` 共享会话。调用 `dbx_execute_batch` 带 `session_id`，设置 `continue_on_error=false`，保持事务选项关闭。结束用 `dbx_close_session`。

目标环境的策略与 MySQL 版本需要在获准的隔离副本核验。MySQL DDL 隐式提交，批处理停止时用 DBX 重查实际列和索引，并保存已完成语句和错误回执。无法确认结果或 DBX 拒绝脚本时保持维护状态，依据已核对的结构审阅剩余语句及下一步。

## 备份范围与恢复验证

- 数据库取停止回执落库后的全库一致快照，涵盖表定义、索引、约束、触发器及业务记录。协作重点含 `tasks`、任务关联数据、`task_dependencies`、`task_execution_attempts`、`task_execution_operations`、`project_device_bindings`、`host_device_authorizations`、`collaboration_batches`、`collaboration_batch_tasks` 及原 OAuth 授权相关表。包含旧四列的值和既有检查点、交付和操作回执。
- 原 JAR 和网页、容器或服务启动参数、工作目录、外置 `.env` 和 `application*`、代理与挂载、附件及文档持久化位置纳入对应时间点的备份。备份放在受控位置，交付清单只登记配置键、来源和恢复坐标。
- 各设备保留原应用或可安装包、LaunchAgent 配置、设备标识及宿主私有状态。旧根记录、运行记录、领取和停止事实与历史快照作为恢复依据保存。项目源文件保留现场。
- 当前 DBX MCP 提供结构查询、固定会话和脚本执行。全量快照与隔离恢复使用目标环境获准的受控备份能力，相关数据库 SQL 仍通过 DBX。分页结果和记录数只用于复核。确认可恢复备份后再执行删列。
- 恢复到隔离目标后用 DBX 检查旧结构、索引、关键业务数据与已收口批次事实，登记备份与恢复对象的标识。生产有新写入或归属不明时，先保留两边数据，再按同边界回滚文档处理。
