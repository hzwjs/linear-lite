# LINEAR-LITE-122 Codex 宿主使用与运行边界 V3

本版对应痕迹协作 V2 和宿主协议 2。V1、V2 文档留作历史记录。

## 连接设备与启动

1. 在项目设置的「本地执行」下载或打开对应版本的 macOS 宿主，选择「连接」完成浏览器授权。升级时使用原站点地址，安装器保留设备标识、授权材料及本机运行记录。旧批次在切换前由原协议收口。
2. 在「项目目录绑定」保存该设备的项目根目录。服务端按用户、项目、设备保存一条绑定，资料目录由项目根下的 `docs` 派生。工作区中的文件供当前项目的 Agent 共享。
3. 在任务里编写需求和完成条件，在任务列表选中目标，从「启动协作批次」选择设备和时长并确认。任务集合在启动时固定，服务端分配并发和尝试预算。网页记录启动请求，刷新或关闭页面后的重试沿用同一操作标识。
4. 在「协作执行」查看服务端预算、截止时间、待领取、缺交付、待复核、等待授权、待恢复或结束状态。在任务详情展开「协作事实」查看发现、采用材料、实际改动和交付依据。业务目标超出原授权时，页面展示目标与影响，确认后由服务端建立新批次。

## 共享工作区与交付

宿主从服务端读取任务和执行事实，Agent 领取任务后读取项目文档及当前文件，再记录采用、缺项、复核或交付。成功交付且前置产物缺失时，下游 Agent 仍可领取并复核，随后按事实在目标内修补、等待变化或发起返工。前置交付本身缺失时，任务保持依赖等待。

受管编辑使用读取版本校验当前文件。同一项目可运行不同批次，同一任务按尝试归属控制领取。编辑事实归属于实际成功的操作。若相关文件在复核或交付前变化，宿主重读并校验版本；历史快照保留成果内容和审计依据。

当前宿主配置将普通 Codex 命令置于只读模式，文件修改经 `host_action` 受管编辑。受管可写命令及其隔离验收由待决的 LINEAR-LITE-144 承担。

## 停止与恢复

1. 在「协作执行」选择批次并点击「停止批次」。关闭网页保留批次的原运行意图、预算和截止时间。
2. 宿主封存对应尝试的编辑入口，排空在途操作，等待已登记的执行进程组退出，再向服务端提交停止确认。网页以服务端停止事实为准。
3. 失联、进程退出无法确认、领取回执缺失或批次接受结果未知时，保留对应运行、尝试、进程组和恢复凭据。恢复按原批次、原代次和归属进行，确认停止后才处理该任务的后续领取。
4. 原宿主恢复连接后按现有恢复入口核验。待恢复期间保留宿主状态和钥匙串，安装器会拦截可能丢失恢复材料的升级和卸载。绑定目录变更在对应运行结束后重试。

停止确认覆盖宿主管理并登记的进程。外部编辑器和未纳入登记的进程变化由后续读取重新核验。

后台用户服务的保活用于连接和接收网页授权的批次。宿主 `plan` 命令返回计划信息和 `enabled: false`，批次定时触发保持关闭。
