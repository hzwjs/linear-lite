# 项目文档表格文档整合方案 V1

日期：2026-10-06

## 1. 推荐方案

采用 **Univer Sheets 开源版**，增加 `SPREADSHEET` 项目文档类型，在独立页面提供电子表格编辑。文档树、项目权限、收藏、归档、保存、搜索和历史版本沿用项目文档体系。

本方案中的“表格文档”指包含工作表、单元格和公式的电子表格。BlockNote 正文内表格继续承担说明文档中的表格排版。

首版采用开源能力，提供工作簿 JSON 导入导出与当前工作表 CSV 导入导出。Excel 文件导入导出、多人协同、图表和透视表不纳入首版；Univer 官方 XLSX 转换属于商业扩展，不能以开源功能交付。[Univer 仓库](https://github.com/dream-num/univer)、[Pro 功能边界](https://docs.univer.ai/guides/pro)、[导入导出服务](https://docs.univer.ai/guides/pro/import-export)

## 2. 开源项目筛选

| 项目 | 许可证与接入方式 | 筛选结论 |
| --- | --- | --- |

以上结论依据项目仓库和官方文档，选型依据为功能、接入方式与许可边界。

## 3. 功能与页面

| 业务入口 | 交付行为 |
| --- | --- |
| 项目文档新建 | 增加“表格”入口，创建包含一个工作表的工作簿；文档标题与工作表名称分开维护 |
| 文档树、收藏、搜索、文档引用 | 展示表格图标；桌面打开独立表格页面；入口依据 `contentFormat` 选择页面 |
| 表格编辑 | 工作表新增、删除、重命名；单元格编辑与粘贴；行列操作；基础格式、合并、冻结；公式计算和撤销重做 |
| 保存 | 沿用文档保存状态与版本冲突提示；标题、单元格、格式、行列和工作表变更触发保存 |
| 历史版本 | 在只读表格组件中预览工作簿；恢复后生成文档新版本，保留恢复前正文 |
| 文件交换 | JSON 保存工作簿结构、公式与格式；CSV 面向当前工作表的值，不承诺保留公式、格式与多工作表结构 |
| 手机阅读 | 在移动端阅读页加载只读工作簿，支持工作表切换与横向滚动；首版编辑入口面向桌面 |

桌面路由采用 `/projects/:projectId/documents/spreadsheet/new` 与 `/projects/:projectId/documents/:documentId/spreadsheet`，沿用 HTML 文档的独立页面模式。树节点或直接链接进入通用文档路由时，应根据类型导向表格页面，禁止落入 BlockNote 编辑器。

## 4. 单一数据路径

```text
project_documents.content_format / content
  → ProjectDocumentResponse.contentFormat / content
  → ProjectDocument.contentFormat / content
  → SpreadsheetDocumentView
  → JSON.parse(content)
  → Univer.createWorkbook(IWorkbookData)

Univer 工作簿变更
  → FWorkbook.save() 工作簿快照
  → JSON.stringify(IWorkbookData)
  → PUT /project-documents/{id}
  → project_documents.content
```

- `contentFormat` 增加 `SPREADSHEET`；`content` 保存一个 Univer `IWorkbookData` JSON 对象。工作簿包含所有工作表，工作表 ID 与工作簿 ID 在保存和恢复时保持稳定。
- 文档标题以 `project_documents.title` 为准。快照中的工作簿名按文档标题生成，禁止通过工作簿名反推标题。
- 不增加 `sheetJson`、`excelContent` 或第二份附件正文，不通过 HTML 或 BlockNote 承载表格数据，不设置格式猜测和多键回退。
- `project_document_revisions` 保存同一 `contentFormat` 与完整工作簿快照。文档类型创建后不允许转换。
- 单元格输入值和公式按 Univer 原生模型保存；公式结果属于计算产物。禁止将计算结果作为第二份可编辑业务数据。
- JSON 文件只作为导入导出介质。导入时生成该文档的工作簿身份，保存后以数据库正文为数据源。

`content` 为 `LONGTEXT`，`content_format` 为 `VARCHAR(16)`，无需新建表或新增正文列。`schema.sql` 更新类型说明；若实施产生 DDL，必须经 DBX 执行并归档到 `schema.sql`，不加入旧字段兼容或数据迁移层。

## 5. 前端整合

采用官方预设接入，新增 `SpreadsheetDocumentView.vue` 与 `SpreadsheetDocumentEditor.vue`。组件职责限定为挂载、变更通知、快照提取、只读切换及资源释放；页面负责文档加载、标题、保存状态、导入导出和历史入口。

2026-10-06 查询 npm 元数据：`@univerjs/presets`、`@univerjs/preset-sheets-core`、`@univerjs/core` 的 latest 为 `1.0.3`。首版将所用 `@univerjs/*` 包锁定同一版本 `1.0.3`；补充 `rxjs` 7.x。`preset-sheets-core` 的 React peer 范围包含 19，项目现有 `react`、`react-dom` 为 `^19.2.5`，不需增加另一套 React。版本范围匹配不代表运行集成完成。[预设包元数据](https://registry.npmjs.org/@univerjs%2Fpreset-sheets-core/latest)、[核心包元数据](https://registry.npmjs.org/@univerjs%2Fcore/latest)

- 按路由加载表格组件、依赖和样式。采用中文语言包，并映射现有界面的主题、标题栏和按钮令牌。
- 在 `onMounted` 创建 Univer，在卸载或切换文档时释放实例和事件订阅；实例不进入 Vue 深层响应式代理。[Vue 接入说明](https://docs.univer.ai/guides/sheets/getting-started/integrations/vue)
- 监听覆盖内容、格式和工作表结构的持久化命令，排除选择、滚动、初始化和公式重算等派生操作；每次编辑结束提取完整快照，不保存尚未提交的输入框文本。
- 复用 `documentStore` 的保存队列和 `expectedVersion`。保存请求中的快照与请求期间的新编辑分开处理；收到旧快照的保存响应时，不重建当前编辑实例。
- 发生 409 冲突后停止自动保存，保留本地工作簿供 JSON 下载，并提供加载服务端版本的操作；不执行单元格自动合并或覆盖服务端版本。
- 历史预览与手机阅读设置工作簿只读权限；隐藏工具栏不能替代只读权限，服务端项目权限是读写边界。[权限说明](https://docs.univer.ai/guides/sheets/features/core/permission)

JSON 导入在浏览器解析后进入同一保存入口。CSV 导入生成当前工作表的单元格输入值，文本不得被识别为公式；CSV 导出采用计算后的可见值，并对公式前缀文本进行转义。首版不使用现有 `xlsx` 包拼接转换器，避免把基础读写误称为 Excel 格式保真。

## 6. 服务端整合

| 现有位置 | 所需变更 |
| --- | --- |
| `ProjectDocumentCommandService` | 增加 `SPREADSHEET` 白名单和 `SpreadsheetDocumentContent` 校验；创建、更新、历史恢复共用校验入口；禁止表格经过 BlockNote 正文工厂 |
| 创建与更新 DTO、响应 DTO | 沿用 `contentFormat` 与 `content`；沿用 `expectedVersion`，不增加表格专属字段 |
| `DocumentRevisionSnapshotService` | 沿用文档的编辑间隔与空闲快照策略；创建、恢复保留完整工作簿。表格自动保存不套用 HTML 的每次保存留档分支 |
| `ProjectDocumentQueryService` | 按类型处理资源；`SPREADSHEET` 返回空 `imageAssets`，不查询 BlockNote 图片引用 |
| `ProjectContentTextExtractor` | 增加表格分支，提取工作表名称、文本或数值输入、富文本正文和公式表达式；按工作表顺序和单元格位置生成搜索文本；不索引公式缓存结果及样式 JSON |
| 文档搜索与索引链路 | 沿用变更事件和现有索引，携带 `contentFormat`，搜索结果导向表格页 |
| `DocumentImageOrphanCleanupService` | 当前正文与历史正文按类型分派；解析 `BLOCKNOTE` 图片引用，表格不进入 BlockNote 数组解析器，避免表格对象阻断项目图片回收 |
| `McpToolRegistry` | `create_document`、`update_document` 的枚举增加 `SPREADSHEET`；`content` 接收工作簿 JSON 字符串，禁止 `images`；`get_document` 返回同一正文，不转 Markdown |

`SpreadsheetDocumentContent` 按锁定版本的模型校验工作簿对象、`id`、`sheetOrder`、`sheets`、工作表身份、行列范围、单元格坐标和公式字段；工作表 ID、顺序、映射须一致。拒绝无法识别的结构、外部资源与外部工作簿引用，不提供解析回退。

首版正文上限定为 UTF-8 5 MiB、20 个工作表、10 万个有内容或格式的单元格；这些数值是产品保护阈值，不是性能承诺。前端导入和服务端写入使用相同限制，超限时提示拆分文档。后端不执行公式，前端采用开源公式引擎，不注册网络函数或用户脚本。

## 7. 实施顺序与取舍

1. 接入开源依赖、中文界面和 `SPREADSHEET` 内容校验，打通创建、编辑、保存、重新打开的工作簿路径。
2. 接入文档树、收藏、搜索、历史恢复、直接链接、手机只读和图片清理类型分派。
3. 接入 JSON、CSV 导入导出及 MCP 原始工作簿读写，完成首版范围。

采用工作簿快照和文档级版本锁，避免新增协同服务与单元格存储模型；代价是保存整份工作簿，多人编辑冲突按整份文档处理。Univer 插件体系比轻量网格增加依赖体积，采用路由加载控制对其他页面的影响。

后续若要求 XLSX 格式保真或多人协同，需要评估 Univer Pro 授权、转换服务部署与数据归属；这些能力具有商业与服务端成本，不能作为首版开源能力的默认承诺。[Pro 授权](https://docs.univer.ai/guides/pro/license)
